# MiniMax Music 本地 API 操作手册

本文根据飞书《MiniMax Music 使用指南》整理，适用于本项目的本地 MiniMax-Music3 全量模型 API：

```text
/home/alone/workspace/minimax-music3-api
```

飞书原文介绍的是 MiniMax 官方网页端 Music-2.5+/2.5/2.0；本地项目使用的是 ModelScope 的 `MiniMax/MiniMax-Music3`。两者都使用“歌词 + 风格/音乐描述”的创作方式，但模型权重、接口和部分限制不同。

## 一、网页功能与本地 API 的对应关系

| 飞书网页功能 | 本地 API 对应字段 |
|---|---|
| 简单模式：只写风格 | `instructions` 写音乐风格；`input` 可写简短歌词 |
| 高级模式：自定义歌词结构 | `input` 写带段落标签的完整歌词 |
| 歌词 | `input` |
| 风格 | `instructions` |
| 歌曲时长 | `duration_seconds`，或官方兼容字段 `max_new_tokens / 25` |
| 模型选择 | 本项目固定为 `MiniMax/MiniMax-Music3` |
| 生成作品 | `/v1/audio/generations` 提交后，从 `/v1/jobs/{id}/result` 下载 |

飞书文档中的“纯音乐开关”属于网页产品能力，本地 API 当前没有单独的纯音乐开关。需要纯音乐时，应在 `instructions` 中明确写“instrumental only、no vocals、no singing”，并将 `input` 设置为简短的器乐主题说明；模型仍可能产生少量人声，不能当作严格约束。

## 二、启动本地服务

### 1. 检查模型是否下载完成

```bash
MODEL_DIR=/home/alone/workspace/minimax-music3-data/models/MiniMax/MiniMax-Music3
du -sh "$MODEL_DIR"
test -f "$MODEL_DIR/configuration.json"
test -f "$MODEL_DIR/language_model/model.safetensors.index.json"
test -f "$MODEL_DIR/transformer/diffusion_pytorch_model.safetensors.index.json"
```

本机实际下载的全量模型约 54GB（包含约 16GB 的语言模型和约 18GB 的 Qwen 7B 分片）。只看到 `.incomplete` 文件时，说明仍在下载，不能启动推理。

### 2. 启动服务

先停止 H3/ComfyUI 等其他 GPU 服务，再执行：

```bash
cd /home/alone/workspace/minimax-music3-api
./scripts/03_start_api.sh
```

默认地址：

```text
http://127.0.0.1:8190
```

局域网访问时使用部署机的局域网 IP，例如：

```text
http://192.168.x.x:8190
```

检查服务：

```bash
curl -sS http://127.0.0.1:8190/health | jq
curl -sS http://127.0.0.1:8190/v1/system/status | jq
```

第一次生成会触发全量模型加载，并执行 CPU/GPU offload，等待时间可能很长。

全量模型约 54GB，而本机内存为 32GB。启动前必须确认 32GB swap 已启用：

```bash
swapon --show
sudo swapon /swapfile-minimax-h3
```

如果进程显示 `Killed`，通常是系统内存不足而不是下载失败；先启用 swap，再重新启动 API。

## 三、简单模式：只描述风格

适合先验证模型和服务，不需要自己设计完整歌词。歌词可以写一两句，也可以让模型根据描述尝试生成；为了结果稳定，仍建议至少提供几行歌词。

```bash
curl -fsS -X POST http://127.0.0.1:8190/v1/audio/generations \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "MiniMax/MiniMax-Music3",
    "input": "[Verse]\n清晨的风吹过城市\n[Chorus]\n我们在阳光下重新出发",
    "instructions": "华语流行音乐，温暖女声，钢琴、木吉他和轻柔鼓组，主歌克制，副歌逐渐开阔，旋律清晰，适合通勤收听。",
    "duration_seconds": 10,
    "seed": 7,
    "response_format": "wav",
    "stream": false
  }' | tee /tmp/music3-job.json | jq
```

取出任务 ID：

```bash
JOB_ID=$(jq -r .id /tmp/music3-job.json)
```

## 四、高级模式：自定义歌词结构

飞书文档建议使用段落标签组织歌曲。本地 Music3 也支持这些标签，标签必须单独占一行，不能和歌词写在同一行。

常用标签：

```text
[intro]       前奏
[verse]       主歌
[pre-chorus]  预副歌
[chorus]      副歌
[hook]        Hook
[drop]        Drop
[bridge]      桥段
[solo]        独奏
[build-up]    情绪递进
[instrumental]器乐段
[breakdown]   结构收束
[break]       间歇
[interlude]   间奏
[outro]       尾奏
```

示例：

```bash
cat > /tmp/music3-lyrics.txt <<'EOF'
[intro]
风从远方来

[verse]
我把昨天写进清晨的云
把未说完的话交给海风听

[pre-chorus]
当城市慢慢亮起来
我知道新的旅程已经到来

[chorus]
我们在光里重新出发
把所有遗憾变成回答
就算远方还有风雨落下
也要唱着歌走到天涯

[bridge]
如果夜色再次覆盖天空
请记得心里的灯还亮着

[outro]
我们在光里重新出发
EOF

LYRICS=$(cat /tmp/music3-lyrics.txt)
curl -fsS -X POST http://127.0.0.1:8190/v1/audio/generations \
  -H 'Content-Type: application/json' \
  --data-binary "$(jq -n --arg lyrics "$LYRICS" '{
    model: "MiniMax/MiniMax-Music3",
    input: $lyrics,
    instructions: "电影感华语流行歌曲，男声温暖而有颗粒感，92 BPM，E 小调。主歌使用钢琴和木吉他，预副歌逐步加入弦乐，副歌加入宽阔鼓组、贝斯和和声，桥段降低密度，尾奏自然收束。",
    duration_seconds: 30,
    seed: 42,
    response_format: "wav",
    stream: false
  }')" | tee /tmp/music3-job.json | jq
```

## 五、风格提示词写法

飞书文档中的“风格”建议在本地 `instructions` 中明确写出以下内容：

1. 类型：流行、摇滚、民谣、电子、古风、爵士等。
2. 速度：BPM；不写时模型会自行决定。
3. 调性：例如 C major、E minor。
4. 人声：性别、音色、演唱方式、是否需要和声。
5. 乐器：钢琴、木吉他、鼓、贝斯、弦乐、合成器等。
6. 结构：主歌如何铺陈、副歌如何增强、桥段如何变化。
7. 场景：电影配乐、夜晚驾驶、咖啡馆、运动、节日等。
8. 制作：温暖、宽阔、现场感、低压缩、近距离人声等。

推荐结构：

```text
Global Metadata: genre, BPM, key, scale, emotional progression.
Vocal Details: vocal gender, timbre, delivery, harmony, vocal effects.
Arrangement: primary instruments, secondary instruments, groove, section evolution, spatial effects.
```

## 六、查询、下载和验证

查询任务状态：

```bash
curl -sS "http://127.0.0.1:8190/v1/jobs/$JOB_ID" | jq
```

状态变化：

```text
queued -> running -> succeeded
                     └-> failed
```

成功后下载：

```bash
curl -fL -o "music3-$JOB_ID.wav" \
  "http://127.0.0.1:8190/v1/jobs/$JOB_ID/result"
```

验证音频：

```bash
ffprobe -v error \
  -show_entries format=duration,size:stream=codec_name,codec_type,sample_rate,channels,bits_per_sample \
  -of json "music3-$JOB_ID.wav"
```

Diffusers 全量管线通常输出 44.1kHz 立体声；如果业务必须使用 32kHz、16-bit WAV，可转换：

```bash
ffmpeg -y -i "music3-$JOB_ID.wav" \
  -ar 32000 -ac 2 -sample_fmt s16 "music3-$JOB_ID-32k.wav"
```

## 七、时长和歌词长度

飞书网页端提示歌词长度会影响成曲时长。本地 API 也建议让歌词量与目标时长匹配，但实际时长由模型结束标记决定，`duration_seconds` 是上限而不是绝对保证。

本地建议按以下顺序测试：

```text
10 秒：服务和模型冒烟测试
30 秒：验证段落结构和人声
60 秒：常规验收
180 秒：长音频和内存压力测试
300 秒：模型上限测试
```

官方兼容字段也可以使用 `max_new_tokens`，每秒约 25 帧：

```json
{
  "max_new_tokens": 750,
  "input": "[verse]\n...",
  "instructions": "..."
}
```

`750` 帧约等于 30 秒，`1500` 帧约等于 60 秒，`7500` 帧约等于 5 分钟。

## 八、纯音乐和中文创作注意事项

纯音乐提示词示例：

```text
Instrumental only, no vocals, no singing, cinematic Chinese orchestral music, erhu, guzheng, large strings, deep drums, gradual build, majestic and spacious.
```

中文歌词建议：

- 每个段落标签单独占一行。
- 不要一次提交过长歌词，先用 10～30 秒测试咬字。
- 中英文混合时，保持每句长度接近，减少节奏漂移。
- 同一个 `seed` 可用于复现结果，但不保证不同硬件或依赖版本完全一致。

## 九、日志和故障排查

日志：

```bash
tail -f /home/alone/workspace/minimax-music3-data/logs/api.jsonl
```

输出：

```text
/home/alone/workspace/minimax-music3-data/outputs/
```

常见问题：

- `CUDA out of memory`：停止 H3/ComfyUI，保持单 worker，降低时长并增加 swap。
- `Killed`：通常是系统内存耗尽，检查 `free -h` 和 `swapon --show`。
- 任务长时间 `queued`：前面已有任务运行；本机单 GPU 设计为串行执行。
- 任务 `failed`：查看对应 JSON 任务文件和 `api.jsonl` 的 `failure` 事件。
- 找不到模型：检查 `config.toml` 的 `model.path`，并确认没有只下载到 `.incomplete` 临时文件。

## 十、与飞书网页端的差异

飞书文档中的 Music-2.5+/2.5/2.0 是官方托管产品，网页端负责模型切换、作品管理、播放和部分提示词辅助。本地项目不包含网页 UI，也不保证支持网页端的所有产品按钮；它只提供本地全量 Music3 的歌词、风格、时长、种子和 WAV 结果接口。
